## OG image

Output: `public/og-image.jpg`, **82 KB**, 1200×630, JPEG.

Format note: brief specified `.png` and `< 100 KB`. Anti-aliased
typography compresses to ~84 KB as JPEG vs ~220 KB as PNG. The
file-size constraint is the harder one (it gates how reliably the
preview renders on mobile data caps), so the format flexed.
LinkedIn / Twitter / Facebook / Slack OG previews accept JPEG
indistinguishably from PNG.

Generated by `scripts/build-og-image.mjs` — self-contained Node
script using macOS `sips` to render an inline SVG. No npm deps. Re-run
on demand:

```sh
node scripts/build-og-image.mjs
```

## Bridge demo — game progress → content reveal (step-by-step)

The bridge is one-way: the game writes, content mode reads.
localStorage is the medium; `useGameProgress()` is the reader hook;
`recordCoin` / `recordProject(id)` / `setHighScore(n)` are the
writers. Perf agent calls the writers from inside the rAF loop.

### Storage keys (created by `lib/mode-toggle.ts`)

| Key | Value | Set when |
|---|---|---|
| `portfolio:hasPlayed` | `'1'` | Any of the three writers fires for the first time |
| `portfolio:coins` | integer (e.g. `'7'`) | Each `recordCoin()` call |
| `portfolio:projects` | JSON array of project IDs (e.g. `'["therasort","data-pipeline"]'`) | Each `recordProject(id)` call (deduped) |
| `portfolio:highScore` | integer (e.g. `'001200'` rendered as `001200`) | `setHighScore(n)` only when `n > current` |

### Demo: never-played visitor

1. Visitor lands on `/`. `useGameProgress()` returns `EMPTY`
   (`hasPlayed: false`, no values).
2. Projects header renders normally. **No badge.** No project card
   has the brick top-accent or coin glyph next to its title. Footer
   has no high-score line.
3. The site looks identical to the pre-bridge version. The
   easter egg is hidden until earned.

### Demo: visitor plays the game and discovers `therasort`

1. From content mode, click the green pipe in nav → `setMode('game')`.
2. In the game, walk into the question block at `lib/level-data.ts`
   (block with `contains: 'project'`, `projectId: 'therasort'`). Perf
   agent's collision handler fires `recordProject('therasort')`.
3. `recordProject` writes to localStorage:
   - `portfolio:projects` → `'["therasort"]'`
   - `portfolio:hasPlayed` → `'1'`
4. It dispatches a `portfolio:progress` `CustomEvent` for same-tab
   reactivity.
5. Visitor clicks "Content mode" → mode toggle returns to content.
6. `useGameProgress` re-reads localStorage on hook re-mount.
   Returned: `{ coinsCollected: 0, discoveredProjects: ['therasort'],
   highScore: null, hasPlayed: true }`.
7. **Projects section header now shows:** "🪙 You found 1/4 projects
   in the Mario level".
8. **The Therasort `<article>`** gets `data-discovered="true"` →
   2px brick top accent + small `<CoinDisc>` next to the heading.
9. The other three project cards still render unchanged.
10. Footer: still no high-score line (`highScore === null`).

### Demo: visitor reaches level-end

1. Perf agent's level-complete handler fires
   `setHighScore(score)`.
2. `setHighScore` writes `portfolio:highScore` only if the new
   score exceeds the stored value.
3. On the next content-mode visit, footer renders:
   `Your high score: NNNNNN` (six-digit zero-padded, in `coin-deep`
   mono font).
4. Cross-tab: opening another tab on the site immediately picks up
   the new score via the `storage` event listener in
   `useGameProgress`.

### Failure modes (graceful)

- **SSR / static export prerender:** `useGameProgress` returns
  `EMPTY` because `typeof window === 'undefined'`. Markup is stable;
  no hydration mismatch.
- **Safari private mode:** every `localStorage.setItem` call is
  wrapped in try/catch. Writers no-op silently. Reader returns
  `EMPTY`. Visitor sees the pre-bridge experience, no console
  errors.
- **Visitor plays but finds nothing:** `hasPlayed: true`,
  `coinsCollected: 0`, `discoveredProjects: []`. Section header
  shows "🪙 You found 0/4 projects" — informative, not patronizing.
- **Hard reload after playing:** badge briefly absent (matches SSR
  markup) → fades in after `useEffect` reads localStorage. The
  alternative (SSR mismatch warning) is worse.
